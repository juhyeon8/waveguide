## 사용자 확정 방향 (Option 1) — 5개 지침 (반드시 준수)

1. **창 끝단 캡(2.5/κ) 즉시 복원.** 엔진 규칙대로. 이건 **측정 버그 수정**이라 논의 대상 아님.
   - κ 측정 창 = 엔진 `kappaFitWindow`: `[0.15L, min(0.7L, 0.15L + 2.5/κ_n)]`, **모드별 κ_n**.
   - 주의: 이 창은 **κ 측정 전용**. k_z 측정([0.2L,0.7L])·그래프 음영·정규화용 `fitWindowZ`는
     현행 유지(k_z 98–102%로 잘 동작 중 — 건드리지 말 것). κ 측정만 새 per-mode 창으로.
2. **dAuto는 0.05λ를 임의로 박지 말고 수렴 스윕으로 결정.** d/λ 0.04–0.10 스윕, 모드별 측정/이론 κ
   기록, **모든 (측정 가능한) 차단 모드가 밴드를 여유 있게 만족하는 가장 큰(=가장 가벼운) d** 채택,
   스윕 결과를 문서화(논문 도선 간격 근거로 재사용).
   - ✅ **스윕 이미 수행 완료** → `docs/wire-spacing-convergence-2026-07-15.md`.
     결론: 단일 c로 엄격 ±5% 전부 만족 불가(③n3 고유 +8% 편향, ①n3 원리적 불가).
     **권고: dAuto=0.055·λ + 판정 밴드 ±10~15%(엔진과 정합) + ①n3류 라벨.** ← 다음 세션 첫
     확인사항(사용자 승인 후 코드화).
3. **정직한 라벨은 유지하되 조건을 좁혀라.** 피팅 구간 안에서 신호가 수치 바닥에 도달해 기울기 측정
   자체가 불가능한 모드(예 ①n3, 1/κ≈6.6셀≈벽간격)에만 "측정 불가(수치 바닥 도달)". **측정 가능한
   모드는 반드시 숫자(측정/이론) 표기.** 라벨이 엔진 부정확성의 은폐 수단이 되면 안 됨.
   - 구현 유의: 바닥 도달 검출은 `measureKappaN`의 현 `<1e-14` 스킵으로는 부족(실제 바닥 ~8e-3).
     창 내 시작/끝 신호비가 작거나(≈1) 기울기≤0/비물리면 "측정 불가"로 판정하는 로직 필요.
4. **부수 문제 — |T| vs κ 민감도.** |T|는 d/λ=0.08서 통과였으나 κ는 어긋남 → **근접차단 κ가 |T|보다
   엄격한 기준.** |T| 경고 임계를 κ 스윕에 맞춰 재조정하거나, 최소한 "κ 정확도 = 벽 무결성의 더 엄격한
   기준(신뢰 d/λ≲0.06)"을 문서·UI에 기록.
5. **성능 저하는 정확도로 갚지 말고 계산 최적화로 흡수.** 드래그 중 디바운스 유지 / MoM 행렬 재사용
   (행렬은 벽 기하+k에만 의존 → **y₀만 바뀌면 동일 행렬 → LU 재사용, |T|는 y₀ 무관하므로 캐시**) /
   필요 시 드래그 중 그리드 해상도 낮추고 놓으면 원해상도 재계산.
   - 유의: `core.js`는 원칙상 수정 금지. LU 재사용은 (a) modes.js/script.js 캐싱 계층으로 하거나
     (b) core.js에 solve-with-new-RHS를 **추가**해야 함 → **범위/엔진 수정 여부는 착수 전 사용자 확인.**
     성능은 dAuto가 확정된 뒤 실제 체감 저하를 측정하고 필요할 때만 최적화(스윕상 d/λ=0.055는 벽
     도선 39~115개 수준, 과도하지 않음).
