# 설계 — 도선 배열 도파관: 입사파 + 산란파로 보는 차단

날짜: 2026-07-08
상태: 사용자 승인 대기
전제 문서: `구현_프롬프트_도선도파관.md` (물리 규약 §1, 코어 이식 규칙 §2, 알려진 함정 §6은 **그대로 준수** — 본 설계는 그 위에 추가 결정만 얹는다)

## 0. 목적과 사용 장면

물리교육 연구자가 **강의 시연(프로젝터)** 에서 사용한다. 도선 두 줄로 도파관 벽을 만들고, 입사파가 도선 전류를 강제해 산란파를 만들며, 그 결과로 차단(cutoff)이 나타나는 과정을 보인다. 핵심 질문: "도선 간격 d를 줄이면 연속 도체판의 차단 거동이 어떻게 나타나는가."

- 큰 글꼴·고대비(프로젝터 대비), 수업 프리셋 버튼으로 흐름 재현.
- 더블클릭(file://) 실행. ES 모듈·fetch·별도 파일 Worker 금지.

## 2. 화면 구성

기존 시뮬(`reference/index.html`)의 다크 테마, 좌측 사이드바 + 세로 패널 구조를 재사용한다.

**헤더**: 제목 "도선 배열 도파관 — 입사파 + 산란파로 보는 차단" + 부제 + 고정 표기 "편광: E∥도선 — 이 편광에는 TEM 모드가 없음".

**사이드바 (위→아래)**:
1. 프리셋 버튼 3개 (§5)
2. 슬라이더
   - 파장 λ: mm + GHz 병기. 범위 = [0.7·2a, 2.0·2a] (a 변경 시 재클램프)
   - 간격 a: "2a = 차단 파장 ○○mm" 병기
   - 도선 간격 d: 기본 5, 범위 2~25 (2 미만은 도선 수 폭증으로 제외)
   - 길이 L: 기본 300
   - (도선 반지름 a_w는 슬라이더 없이 0.8 고정 — 자유도 축소. 단 a_w ≤ d/4, a_w ≤ λ/20 위반 시 경고 규약은 유지)
3. 입사 토글: [평면파 (입구 결합)] / [선원파 (x=−80, y=0)]
4. 애니메이션: 재생/일시정지, 속도
5. 정보 박스
   - 차단/전파 배지: "차단: λ > 2a → 감쇠파" / "전파: λ < 2a → 모드 진행"
   - 이론 κ 또는 k_z + 측정값 + 백분율. ±15% 밖 → 주황 경고 + "d 감소 권장"
   - **도체판 근사 게이지**: 측정/이론 비를 막대로 — "이 도선 벽은 지금 몇 % 도체판인가"
   - 투과율: 전파 시 % / 차단 시 "감쇠 ○○dB (L=○○ 기준)" + "○○dB/mm" (규약 §1-5)
   - 누설 지표: 도선 사이 중간점(벽 위, y=±a/2) |E| 평균
   - 입구 앞 정재파: x<0, y=0 축의 |E| 최대/최소 비(SWR) + 반사율 추정. 캡션: "차단 시 입사 에너지는 흡수되지 않고 반사된다. 입구 앞 정재파가 그 증거."

**패널 (세로 5단)**:
1. ① 입사파 — 평면파/선원파만. 평면파 시 캡션: 도파관 바깥에도 평면파가 그대로 존재함(물리적 실재) 한 줄
2. ② 산란파 — 부제 "도선 표면 E=0이 강제한 산란파". 도선 점 + **전류 위상자**
3. ③ 전체장 (①+②) — 도선 점 + 전류 위상자. ①+②를 눈으로 더하면 ③
4. ④ |c₁(x)| 진단 그래프 — 측정 실선 + 이론 점선(차단 exp(−κx) / 전파 상수), 가로축은 ①~③과 동일 픽셀 매핑
5. ⑤ T(λ/2a) 스윕 — d=5/10/20 곡선 + 현재 λ 수직 마커 + λ/2a=1 차단선. "스윕 계산" 버튼 + 진행률. 파라미터(a, L) 변경 시 곡선을 흐리게 처리(스테일 표시)

**전류 위상자 (핵심 신규 요소)**: ②·③의 도선 점 색상(hue) = arg(c_j) + 애니메이션 위상 φ, 진폭은 점 크기 또는 채도로. 색상환 범례 필수. 목표 장면: 전파 = 벽을 따라 위상 전진(파도타기) / 차단 = **전 도선 동위상, 진폭만 감쇠**. 차단 영역에서 위상 "수치·차이"는 어디에도 표기하지 않는다(규약 §1-3).

```
슬라이더 변경
  → solveMoM (10–100ms, 도선 ≤ 302개)
  → 그리드 복소장 계산: E_inc[re,im], E_scat[re,im] (룩업 테이블)
      드래그 중: 저해상도 → idle: 고해상도 재계산
  → 진단: modeCoefC 샘플 → κ 피팅(kappaFitWindow 규칙 고정) 또는 k_z 측정
  → 정보 박스 갱신 + 경고 판정
애니메이션 프레임 (재계산 없음)
  → 픽셀별 re·cosφ + im·sinφ → 색 매핑 → ①②③ 캔버스
  → 도선 위상자 hue 회전
스윕 버튼
  → (d, λ) 격자: d ∈ {5,10,20}, λ/2a 0.7~2.0을 24점
  → 점당 solveMoM + 입출구 |c₁| (±0.04L 평균, D6) → T = |c₁out/c₁in|²
  → chunked 계산, 진행률 표시, 완료 시 ⑤ 갱신
```

**T 측정 규약(공통)**: 입구 x=0.12L, 출구 x=0.88L 기준(프롬프트 §1-5), 각각 ±0.04L 구간 |c₁| 평균(D6). 스윕도 동일 규약. 스윕 캡션: "평면파 입사, L=현재값 기준. 차단 쪽 값은 길이에 따라 달라진다."

## 6. 성능 예산

- MoM: L=300, d=5 → 122도선, 10–100ms. 최악(L=400, d=2) 402도선 → 수백 ms: d 하한 2 + L 상한 400으로 상한 고정, 초과 시 debounce.
- 그리드: 고해상도 520×220 × 도선 122 ≈ 1.4×10⁷ 룩업 → 수백 ms 가능. 드래그 중 260×110(¼ 비용) 프리뷰. `k·r` 인덱스 계산은 x·y 거리 제곱 테이블 없이 직접 hypot(픽셀·도선 이중 루프, Float32Array).
- 애니메이션: 저장된 re·im에 위상 회전만 — 3패널 × 114k픽셀 × 60fps는 typed array로 충분.
- 스윕: 3d × 24λ = 72 solveMoM ≈ 2~7초 → chunked + 진행률.

## 9. 구현지시(0708) 반영 — A1~A7

- **A1**: 투과율·⑤스윕은 **평면파 전용**. 선원파 시 투과 라벨 숨김, |c₁| 감쇠+κ만 표시, 스윕 버튼 비활성(툴팁 "평면파 전용").
- **A2**: SWR·반사율도 **평면파 전용**. 선원파 시 숨김.
- **A3**: 입출구 |c₁| 완화 = **기하평균** `exp(mean(log|c₁|))`. 스윕도 동일.
- **A4**: 도체판 게이지 캡션 추가 + 전파 영역에선 누설 지표를 게이지와 동등 부각.
- **A5**: ④ 그래프 캡션 "세로축은 그래프 자체 정규화 — 패널 색 밝기와 직접 비교 금지".
- **A6 (부호 확정)**: 전류 위상자 순시값 = **`c_j.re·cosφ + c_j.im·sinφ`**. 지시문 A6의 `−cim·sinφ`(=Re(c·e^{+iφ}))는 장 렌더링 규약(`re·cosφ+im·sinφ`, core.js 12행·reference drawField와 동일 = Re(F·e^{−iφ}))과 **부호가 반대**여서, 그대로 쓰면 도선 점이 자신이 만든 근접장과 **역위상으로 깜빡여** "전류가 장을 만든다"는 인과가 색으로 깨진다. → 장과 부호를 통일해 `+`로 확정. 표시: 순시값 부호로 빨강/파랑, |순시값|로 채도·크기. 차단 영역에선 위상 각도·눈금값 표기 금지, 범례는 "전 도선 동위상"으로 대체.
- **A7**: reference를 테마색·mm규약(=2)·색매핑(`colorForValue`)의 단일 출처로 삼고 값을 새로 짓지 않음.

**확장(신규 코드):**
- `field.js`: `addWireSource` — reference `addOneSource`는 실수 부호(±1)만 곱함. 도선은 **복소 진폭 c_j**이므로 `re += cre·h_re − cim·h_im; im += cre·h_im + cim·h_re`로 확장. 이것이 field.js의 핵심 신규 코드.
- `render.js`: `drawWirePhasors` — reference `drawSourceDots`는 고정 색(부호). 도선은 **매 프레임 순시 전류값**(A6)으로 recolor.
- `style.css`: `.panels`를 2열 → **①②③④ 단일 열(전폭, x축 픽셀 공유)**로. ⑤ 스윕은 별도. 프로젝터용 글꼴 확대·게이지·위상자 범례.

**재사용 금지 (충돌):**
- reference main.js `computeFitInterval`(x0+20~x0+70)은 영상법 전용 — **쓰지 말 것**. κ 피팅 구간은 core.js `kappaFitWindow`(0.15L ~ min(0.7L, +2.5/κ)) 규칙 고정(프롬프트 §2·§6).
- reference physics.js `computeModeField`(무한 평행판 모드 합)는 이 시뮬과 무관 — 사용 안 함.

## 11. 렌더 좌표 (신규 결정)

- reference는 무한 평행판이라 x<0 개념이 약함. 도선 도파관은 **입구 앞 정재파(x<0)** 를 보여야 하므로 x-오프셋 도입: `xPix = xCell + xLeft`, `xLeft ≈ 110`(선원 x=−80 + 정재파 구간 포함), 오른쪽 여유 `xRight ≈ 110`.
- `Nx = xLeft + L + xRight` (L에 따라 가변; 캔버스 CSS는 100% 폭이라 컨테이너에 맞춰 표시). y축은 reference와 동일 `Ny=220, y0=110`, 도파관 벽 y=±a/2를 y0 기준 픽셀로 매핑.
- 패널 순서: ① 입사 / ② 산란 / ③ 전체 (프롬프트 §3 — ①+②를 눈으로 더하면 ③). reference HTML의 inc/tot/scat 순서와 다르니 주의.

## 12. 검토 보강 (2026-07-08, 설계 최종 확정 전 3개 항목)

§10·§11의 결정에서 파생되는 미세 정합 항목. 구현 중 어긋나기 쉬우므로 명시한다.

- **C1 — 그리드 모드계수 교체 시 재검증.** §10에서 속도를 위해 진단을 core의 per-point `modeCoefC`(/nY 정규화) 대신 그리드 기반 `modeCoefficient`(/span 정규화)로 바꾼다. 정규화 상수가 달라도 κ 피팅(로그 기울기)·T(입출구 비)에서는 소거되어 결과가 같아야 한다. 단 selfTest는 `modeCoefC`로 통과한 값이므로, §7-2 콘솔 검증에서 그리드 기반으로 교체한 뒤 κ·k_z가 여전히 이론 ±15% 안에 드는지 반드시 재확인한다. 벗어나면 정규화/샘플링(그리드 j 범위)이 원인이므로 core 값과 대조해 맞춘다.
- **C2 — a 슬라이더 step=2 (짝수 픽셀 고정).** `modeCoefficient`는 jBot=round(y0−a/2), jTop=round(y0+a/2)로 벽을 반올림 매핑한다. a가 홀수 픽셀이면 span 반올림이 흔들려 sin 가중이 미세하게 비대칭이 된다(selfTest a=60 짝수라 무영향이었음). a 슬라이더 step을 2로 두어 짝수 픽셀만 허용하면 이 문제가 원천 차단되고, mm 환산(×2, D8)과도 정수로 맞아떨어진다. 셀 단위 내부 상태는 짝수, 표기는 mm.
- **C3 — 스윕 스테일 처리 확인(신규 아님, 정합 확인).** §4 스윕의 λ/2a 0.7~2.0 범위는 D2의 λ 슬라이더 클램프 범위와 동일하다(일관). 스윕 곡선은 "현재 a·L 기준"이므로 a 또는 L 변경 시 D1대로 곡선을 흐리게(스테일) 표시한다. 별도 구현 아님 — D1·D2가 이미 커버함을 확인만.
