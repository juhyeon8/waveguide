# 설계 문서 — 도체도선배열을 이용한 입사파-산란파 중첩 모형

- 작성일: 2026-07-14
- 상태: 검토 대기 (사용자 리뷰 후 구현 계획 단계로)
- 산출물: 단일 페이지 시뮬레이션 (탭 분리 없음)

---

## 1. 목적

도체 도선을 두 줄로 배열해 도파관 벽을 구성하고, 각 도선 표면의 경계조건(MoM)으로부터
산란파를 결정한다. 도파관 내부 장이 **여러 횡방향 모드의 합**으로 구성됨을 보이고,
파장에 따라 하나의 화면에서 연속적으로:

1. λ가 매우 길면 → 모든 모드 차단(입구 근처 지수 감쇠)
2. 적당히 길면 → mode 1만 전파
3. 짧으면 → mode 2, mode 3까지 전파

이때 **모드는 계산된 장을 분해해 얻는 출력**이지 입력이 아니다. 모드 전개식은 이론
비교선 용도로만 쓰고, 장 자체는 오직 "입사파 + 도선 산란파 합"으로만 생성한다.

---

## 2. 좌표·기호 규약 (확정)

도파관 표준을 따른다. **코드 변수명과 화면 라벨을 모두 이 규약으로 통일한다.**

| 기호 | 의미 | 범위 |
|------|------|------|
| `z` | 파동 진행축(도파관을 따라가는 방향) | `0 … L` |
| `y` | 횡방향(폭 a, 벽에서 벽까지) | `0 … a` (벽: y=0, y=a) |
| `sin(nπy/a)` | n차 횡방향 모드 프로파일 | n = 1, 2, 3 |
| `y₀` | 소스 도선의 횡방향 위치 | `0.05a … 0.95a`, 기본 `a/2` |
| `z₀` | 소스 도선의 축방향 위치 | 관찰 구간보다 앞선 고정점 (아래 §5) |

> **기존 코드와의 관계:** 현재 앱(main.js 등)은 진행축을 `x`로 쓴다. 새 페이지의 코드·라벨은
> 전부 `z`로 쓴다. 공유 엔진 `core.js`는 좌표 이름이 붙지 않은 순수 수치 함수이므로 내부를
> 고치지 않고, 호출 경계에서 `(z, y)`를 core의 위치 인자에 그대로 넘긴다(§3 어댑터 참고).

## 3. 아키텍처 — 엔진 재사용 + 신규 뷰

### 3.1 절대 유지 조건 (물리 엔진)

- 입사파 = **소스 도선의 원통파 H₀⁽¹⁾** (`core.js: incLine`).
- 벽 도선 = 두 줄로 이산 배치, 각 도선 표면(반경 r_w)에서
  **[입사파 + 모든 도선의 산란파 합 = 0]** 을 점정합으로 부과 → 전류 c_j 연립방정식으로 풀이
  (`core.js: solveMoM`).
- 전체장 = 입사장 + 산란장 (`core.js: totalField`).
- **영상법 금지. 모드 전개로 장 생성 금지.**

### 3.2 엔진 추출 확인

`core.js`는 이미 의존성 없는 독립 모듈이다(브라우저에서 `WireWG` 전역으로 노출, `<script src>`로
로드 가능). 그리드 렌더용 `field.js`·`hankel.js`도 독립적이다. 따라서 **엔진은 그대로 재사용**한다.

> 구현 착수 시 첫 단계로 `core.js`·`field.js`·`hankel.js`가 다른 앱 파일에 숨은 의존 없이
> 단독 로드되는지 확인한다. 숨은 결합이 발견되면 **기존 동작을 바꾸지 않는 범위에서 엔진만
> 먼저 깨끗이 추출**한 뒤 진행한다. (기존 `index.html`/`main.js` 동작은 보존.)

### 3.3 파일 배치 (되돌리기 안전)

기존 시뮬을 건드리지 않도록 **하위 폴더에 새 페이지**를 만든다. 더블클릭으로 열린다.

```
higher-order/
  index.html      새 페이지 마크업
  style.css        새 페이지 스타일
  script.js        상태·컨트롤·렌더·모드분해·이론선 (신규)
core.js            [재사용] <script src="../core.js">
field.js           [재사용] <script src="../field.js">
hankel.js          [재사용] <script src="../hankel.js">
```

기존 루트 `index.html`(현재 시뮬)은 그대로 둔다. "기존 시뮬 삽입 여부"는 추후 결정.

### 3.4 좌표 어댑터

`core.js`의 함수는 위치 인자 `(x, y)`를 받는다. 새 페이지에서 진행축은 `z`이므로
호출부에서 `z`를 core의 첫 위치 인자로 전달한다. 즉 새 코드 전역에서 변수는 `z`,
core 호출 시에만 위치로 대응. 별도 이름 변환 레이어 없이 주석 한 줄로 명시한다.

## 4. 파장 영역과 프리셋

`λ/a` 슬라이더 (범위 **0.4 – 2.5**), 프리셋 버튼 4개:

| 프리셋 | λ | 대역 | 기대 결과 |
|--------|-----|------|-----------|
| ① 완전 차단 | 2.4a | λ > 2a | 모든 모드 차단, 입구 근처 지수 감쇠 |
| ② 단일 모드 | 1.5a | a < λ < 2a | mode 1만 전파 |
| ③ 2모드 대역 | 0.8a | 2a/3 < λ < a | mode 1·2 전파 가능(단 mode 2는 소스가 중심을 벗어나야 여기) |
| ④ 3모드 대역 | 0.55a | λ < 2a/3 | mode 3까지 전파 |

- 프리셋 ③ 버튼은 소스를 `y₀ = a/4`로, ④ 버튼은 `y₀ = a/6`로 **함께 이동**시켜
  사용자가 mode 2·3을 실제로 볼 수 있게 한다.
  - `y₀=a/6`에서 세 모드 결합은 `sin(π/6)=0.5`, `sin(2π/6)=0.866`, `sin(3π/6)=1` — 셋 다 0이 아니라
    n=1,2,3이 모두 실린다(의도된 설정, §10-4와 정합).
- **n≥4 미표시:** λ ≲ 0.5a에서는 mode 4 이상도 전파하지만 분해 그래프는 n=1,2,3만 표시한다.
  화면과 코드 주석에 "n=1–3만 분해 표시(n≥4 미표시)"를 명시한다.

## 5. 소스 도선 제어

- **횡방향 y₀:** 슬라이더 `0.05a … 0.95a`, 기본 `a/2`(도파관 중심). 옆에 **"중심으로"** 버튼
  (한 번 클릭으로 y₀ = a/2 복귀).
- **결합 세기 상시 표시:** 각 모드의 `|sin(nπy₀/a)|`를 수치로 항상 보여준다.
  중심(y₀=a/2)에서 n=2 결합이 **정확히 0**임이 드러나야 한다(대칭에 의한 짝수 모드 배제).
- **축방향 z₀:** 슬라이더 없이 **고정**. 관찰 구간(모드를 읽는 z 구간)보다 **앞선 지점**에 둔다.
  a의 배수가 아니라 "관찰 구간 앞"이라는 기준으로 잡는다. 구현 기본값: `z₀ = 0.12·L`.
  소스–관찰 구간 여유는 고정 상수가 아니라 **κ 스케일**로 잡는다(§6.5) — 차단 문턱 근처에서 κ가
  작을 때 소스 근처 과도장이 멀리까지 새어 피팅을 오염시키는 것을 막기 위함.

## 6. 표시 요소

### 6.1 2D 장 히트맵

- `Re(E_z)` 순간장. 위상 진행 애니메이션은 **복소장에 e^(−iφ)만 곱해 렌더만 갱신**(재계산 금지).
- 벽 도선과 **소스 도선 위치** 표시.
- `prefers-reduced-motion` 시 정지 프레임.
- 색 스케일: 프리셋 ①처럼 장이 빠르게 소멸하는 경우, 전역 최대 고정이면 아무것도 안 보이므로
  **입구/관찰 구간 근처 값에 맞춰 스케일 조정**.

### 6.2 모드 세기 그래프 (z에 따른 모드 결합 세기)

- 계산된 장을 각 z 단면에서 `sin(nπy/a)`에 사영해 `|cₙ(z)|`를 **로그 축**으로 그린다 (n=1,2,3).
- 색·선 규약:
  - mode 1: 실측 = **파란 실선**, 이론 = 파란 점선
  - mode 2: 실측 = **초록 실선**, 이론 = 초록 점선
  - mode 3: 실측 = **주황 실선**, 이론 = 주황 점선
  - 범례에 **실선 = 실측(MoM), 점선 = 이론** 명시.
- **정규화:** 모든 모드 **공통 기준 하나**(관찰 구간 시작 단면의 최대 모드 진폭)로 통일.
  모드별 자체 정규화 금지.

### 6.3 이론 비교선

- **차단 모드:** 관찰 구간 기준점에서 실측값에 앵커한 지수 감쇠 점선
  `e^(−κz)`, `κ = √((nπ/a)² − k²)`.
- **전파 모드:** 수평 점선. 높이는 도파관 그린 함수 전개의 모드 진폭 비율
  `|sin(nπy₀/a)| / k_{z,n}` 로 예측한 **상대 높이**를 쓰고, 전체 스케일은 **mode 1 실측 평균**에
  앵커한다. 이로써 모드 간 상대 세기까지 이론과 비교된다.
- **앵커 충돌 주의(§6.2와의 관계):** §6.2의 공통 정규화 기준(관찰 구간 시작 단면 최대 진폭)과
  달리 전파 이론선은 mode 1 실측에 앵커한다. 따라서 **mode 1은 자기 자신에 앵커 → 실측선과
  이론 수평선이 거의 겹치는 것이 정상**이다. 구현자가 두 앵커를 억지로 맞추려 하지 말 것.
  **이론 비교의 검증력은 mode 2·3의 상대 높이**(mode 1 대비 `|sin(nπy₀/a)|/k_{z,n}` 비율)에서
  나온다.

### 6.4 수치 비교 표시

- 전파 모드: `cₙ(z)`의 위상 기울기에서 측정한 `k_z` vs 이론 `√(k² − (nπ/a)²)`.
- 차단 모드: `ln|cₙ(z)|` 기울기에서 측정한 `κ` vs 이론값.
- 결합이 거의 0인 모드: **"여기되지 않음(마디 위치)"** 로 표시.

### 6.5 관찰(피팅·정규화) 구간

소스 과도장과 끝단 반사를 **모두 피한 중간 z 구간**으로 잡는다.
`core.js: kappaFitWindow`의 규칙(끝 `min(L·0.7, 시작+2.5/κ)`)을 재사용·확장하되, **시작을 κ 스케일
여유로** 정한다:

```
z_start = clamp( z₀ + 2/κ_min ,  0.2L ,  z_start_cap )
```

- **여유 = 2/κ_min** — 그 조건에서 가장 작은(가장 느린) 감쇠율의 역수 스케일. 소스 근처
  비전파 과도장이 이만큼 뒤에서는 충분히 사그라든다.
  - **κ_min 정의:** 현재 λ에서 **차단 상태인 모드(n=1,2,3 중)들의 최소 κ**. (κ가 작을수록 과도장이
    멀리 새므로, 가장 작은 κ가 여유를 지배한다.)
  - **⚠ NaN 분기(구현 시 반드시 확인):** 전파 모드만 있고 **차단 모드가 하나도 없는 경우**
    (예: 짧은 λ에서 n=1,2,3 모두 전파) `κ_min`이 없어 `2/κ_min`이 정의되지 않는다. 이때는
    여유 항을 쓰지 말고 **하한 `0.2L`로 떨어지는 분기**를 둔다. 이 분기가 빠지면 NaN이 발생한다.
- **하한 0.2L** — 여유가 작아도 최소한 소스에서 이만큼은 떨어뜨린다.
- **상한 `z_start_cap`(예: 0.5L)** — κ가 매우 작아(거의 전파 문턱) 여유 `2/κ_min`이 과도하게
  커지면, 관찰 구간이 사라지지 않도록 시작을 이 값으로 제한한다.

## 7. 도선 간격 d 자동 연동 + 벽 무결성 (핵심)

### 7.1 자동 연동 토글

- **체크박스**로 on/off. **기본 상태: 켜짐.**
- **켜짐:** `d_auto = clamp(0.08λ, d_floor, 0.1λ)`. d 슬라이더는 **비활성**(값 표시만).
  - **상한 `0.1λ` (벽 무결성):** 벽 무결성은 오직 상한 `d/λ ≤ 0.1`로만 보장한다.
  - **하한 `d_floor` (계산 보호):** 하한의 목적은 벽 무결성이 아니라 **도선 총수 폭증 방지**다.
    셀 고정값이 아니라 **도선 총수가 상한 `N_max`를 넘지 않도록 필요한 최소 d**로 정의한다:
    `d_floor = L / N_max`. (λ가 클 때 셀 고정 하한 때문에 도선이 과도하게 촘촘해지는 상황을
    피하는 것이 목적이며, 목적=계산 보호 / 수단=벽 무결성 상한을 뒤섞지 않는다.)
    구현 착수 시 계산시간 실측으로 `N_max`를 정한다(§9 참고).
- **해제:** d 슬라이더를 **활성화**해 사용자가 직접 조절.

### 7.2 벽 무결성 지표 (두 모드 모두 상시 표시)

- **평면파 입사 투과 계수 |T|** 와 **d/λ** 를 항상 표시한다.

**|T| 정의 확정 — (a) 유한 배열 누설.**
두 정의 중 **(a) 유한한 두 줄 도선 배열의 누설**을 채택한다(무한 주기 단위셀 (b)는 채택 안 함).
이유: 지표의 목적은 |T|의 절대값이 아니라 **d/λ 증가에 따른 |T| 증가 경향**을 보여주는 것이고,
(a)는 시뮬레이션이 이미 만드는 유한 배열·동일 MoM 행렬을 그대로 재사용해 구현이 단순하다.
가장자리 회절이 절대값에 섞이는 것은 감수한다(경향 관찰이 목적).

- **입사:** 평면파가 **벽에 수직**으로(벽면을 향해) 입사.
- **투과 = 벽 반대편으로 새는 장의 비율:** 입사원 반대쪽(벽 너머) 영역에서 새어 나온 장의 세기를
  입사 세기로 정규화한 값.
- **풀이:** 같은 도선 배열에 평면파를 입사시킨 **보조 MoM 풀이**. 선원 풀이와 **동일한 MoM 행렬 A**를
  공유하므로 우변(b)만 바꿔 두 번 푸는 방식으로 비용 절감 가능(LU 재사용은 선택 최적화).
- 수동 모드에서 λ를 줄이거나 d를 키워 **d/λ가 커지면 |T|가 증가**하며 벽이 무너지는 과정을
  직접 관찰할 수 있어야 한다.

### 7.3 붕괴 경고

- 벽 무결성이 임계 이하로 나빠지면(예: `|T|`가 임계 초과 또는 `d/λ > 0.1`),
  **모드 분해 그래프에 "벽 근사 무너짐 — 모드 분해 신뢰도 낮음" 경고**를 표시한다.
- 목적: 이론선과의 불일치가 **버그가 아니라 물리적 붕괴**임을 명확히 한다.

```
   ├─ buildWires(a, L, d, r_w)                        도선 기하
   ├─ incFn = incLine(k, z₀, y₀)                      입사파(소스)
   ├─ solveMoM(wires, k, incFn) -> c_j                경계조건 -> 전류
   ├─ [보조] solveMoM(wires, k, incPlane) -> |T|       벽 무결성(행렬 공유)
   ├─ 그리드: incident + scattered = total (field.js/hankel.js)
   ├─ modeCoefN(total, n=1..3) -> cₙ(z)               모드 분해(신규, sin(nπy/a))
   ├─ 이론선: 차단 e^(−κz) / 전파 |sin(nπy₀/a)|/k_z
   └─ 측정 k_z·κ (관찰 구간 피팅)
   |
[애니메이션 프레임]  e^(−iφ)만 곱해 렌더 (재계산 없음)
```

- 슬라이더는 `input`으로 **수치만 갱신**, 재계산은 `change` 또는 **150ms 디바운스**.
- 신규 함수 `modeCoefN(...)`은 기존 `modeCoefC`(n=1 하드코딩)를 n 파라미터로 일반화한 것.
  기존 함수는 건드리지 않고 새 페이지 코드에 일반화 버전을 둔다.
- **입사/산란 분리 유지:** 3분할 패널은 범위 밖(§11)이나, 논문이 "입사파+산란파 중첩"을
  강조하므로 데이터 흐름은 **입사장과 산란장을 각각 반환·분해할 수 있는 구조**로 유지한다.
  즉 그리드 계산은 `incident`·`scattered`를 따로 보관한 뒤 합하고(이미 field.js가 분리 보관),
  `modeCoefN`도 전체장뿐 아니라 입사장·산란장에 대해 각각 사영할 수 있게 장 인자를 받는 형태로
  둔다. (추후 3분할 패널이 필요해질 때 흐름 재설계 없이 표시만 추가하면 되도록.)

## 9. 오류·경계 처리

- **λ 최소(0.4a)에서 도선 수 최대** → 행렬 크기·계산 시간 확인. 필요 시 격자 해상도 조정,
  디바운스로 드래그 중 과부하 방지. (참고: core.js 검증 노트 기준 122도선 ≈ 10–100ms;
  자동연동 최소 λ에서 대략 300도선대 예상 → 보조 풀이 포함 계산시간 실측 후 조정.)
- **완전 차단(①)** → 색 스케일을 관찰 구간 값에 맞춰(§6.1).
- **끝단 반사 잔물결** → 물리 현상이므로 제거하지 않고, 피팅·이론선 앵커를 끝단에서 떨어뜨려 처리(§6.5).
- **결합 ~0 모드** → "여기되지 않음(마디)".
- **벽 붕괴** → 크래시가 아니라 경고 배너(§7.3).

## 10. 검증 기준 (구현 후 반드시 확인)

1. 프리셋 ①(λ=2.4a): 세 모드 모두 지수 감쇠, mode 1 감쇠가 이론 점선과 일치.
2. 프리셋 ②: mode 1만 평평, mode 3은 이론 점선과 일치하는 감쇠, mode 2는 노이즈 바닥
   (중심 소스 → 결합 0).
3. 소스가 중심일 때 λ를 어떻게 바꿔도 mode 2가 안 나타남. y₀를 a/4로 옮기는 순간
   (λ<a 조건에서) mode 2가 나타남.
4. 프리셋 ④ + y₀=a/6: 세 전파 모드가 모두 실린다(결합 `sin(π/6)=0.5`, `sin(2π/6)=0.866`,
   `sin(3π/6)=1` — 셋 다 0이 아님, 의도된 설정). 세 모드 상대 높이가 이론 `|sin(nπy₀/a)|/k_{z,n}`
   비율과 **대체로 일치**.
   - **허용 오차(정밀 일치 아님):** 이론값은 이상적 도파관 기준이고 실제 MoM에는 소스 근처 결합,
     유한 벽 길이, 끝단 반사가 섞인다. 기대 수준은 **모드 간 높이 순서와 대략적 배율
     (order-of-magnitude 및 대소 관계)까지의 일치**다. 정밀 일치가 목표가 아니며, 정확히 안
     맞는다고 엔진을 의심하지 말 것.
5. 측정 k_z·κ가 이론값과 수 % 이내 일치. 어긋나면 도선 간격·피팅 구간·끝단 반사 점검.
6. 수동 모드에서 d/λ를 키우면 |T| 증가 + 임계 이하에서 붕괴 경고 표시.

엔진 자체는 `core.js`의 `selfTest()`(κ·k_z 이론 대비 %)를 그대로 회귀 검증에 재사용한다.

**⚠ "화면이 그럴듯하다"에서 멈추지 말 것 (수치 관문).** 검증 기준 1–6은 첫 실행 후 **실제로
통과하는지가 진짜 관문**이다. 특히 **기준 5(측정 k_z·κ가 이론과 수 % 이내)가 어긋나면 그 아래
모든 그림의 신뢰가 무너진다.** 구현자는 시각적 그럴듯함에서 멈추지 말고, **`selfTest()` 수치와
관찰 구간 피팅 결과(각 모드 측정 k_z·κ와 이론 대비 %)를 로그로 찍어 확인한 뒤 보고**한다.

## 11. 범위 밖 (YAGNI)

- 탭 분리 / 기존 시뮬 삽입 — 추후 결정.
- z₀ 슬라이더(축방향 소스 이동) — 고정으로 충분.
- n≥4 모드 분해 — 미표시.
- 입사/산란 분리 **3분할 패널은 범위 밖**(전체장 단일 히트맵)이나, **데이터 흐름은 입사/산란
  분리가 가능하도록 설계 유지**(§8) — 추후 패널이 필요해지면 표시만 추가.
